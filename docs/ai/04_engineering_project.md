## 1. Scope

This page explains where Jugg's project snapshots originate, how IDE, Gradle, and included-build data merge, and how the result serves compilation, deployment, dependency changes, and androidTest.

For implementation of compilation stages, deployment state machine, and androidTest execution, see `02_compile_core.md`, `03_deploy_complete.md`, and `06_android_test.md`.

## 3. Core Data Model

### 3.1 Paths and Persistence

| File/directory | Producer | Purpose |
|---|---|---|
| `build/jugg/database/project_infos.db/project_infos.json` | IDE | Raw IDE project-info snapshot, not the final merged result. |
| `build/jugg/database/project_infos.db/gradle_project_infos.json` | Gradle init script | Reflectively read Gradle module/dependency/variant snapshot. |
| `build/jugg/database/project_infos.db/include_build_*_gradle_project_infos.json` | Included-build Gradle init script | Module/dependency/variant snapshot for an included build. |
| `build/jugg/database/project_infos.db/gradle_include_builds.txt` | Gradle init script | Included-build project-info file list. |
| `build/jugg/database/project_infos.db/is_dirty` | Project-info management | Marks project info for refresh. |
| `build/jugg/classpath/` | Gradle/full-build fetch | Local classpath, APK, library backup, embedded APK. |
| `build/jugg/classpath/native_strip/` | Gradle init script (written during full build) | APK-owner `keepDebugSymbols` and ABI strip-tool cache, with `config.json` and copies of tools under `tools/` migrated with baseline. Outside `classpath/root`, so excluded from Java/Kotlin classpath. |
| `~/.jugg/library_test_build_records` | androidTest history | History of self-targeting library Test APK builds. |
| `build/jugg/config/run_configurations/<id>.json` | IDEA / standalone | Independent CLI build profile with stable UUID ID unaffected by rename. |
| `build/jugg/config/current_run_configuration.json` | IDEA / standalone | Current-configuration pointer containing only schemaVersion and configId. |
| `build/jugg/runtime.lock.owner.json` | Runtime holding Project Runtime lease | Written when first project task of that Runtime obtains lease; removed when last reference is released. |
| `build/jugg/runtime.owner.json` | `TaskRunnerManager` | Last IDEA/standalone Runtime with project write ownership. CI does not write it. Temporary-file atomic replacement; corrupt content means no historical owner and is overwritten by current Runtime. |
| `~/.jugg/locks/standalone.launch.lock` | Python CLI | Process-level lock for automatic standalone launch; Runtime is rediscovered under the lock to prevent concurrent daemon creation by different projects. |

IDEA Jugg Run Configuration is the synchronization source for shared profiles. On project startup, save current IDEA configurations over stored versions by stable UUID and write the selected Jugg Configuration into the pointer. Renaming thus does not create a new profile, and remote switch, authentication, and Gradle command do not retain snapshots from the previous IDE exit. Later selection/edit events keep the same `save + select` contract.

`GradleProjectInfoReaderManager` first reads Gradle property `jugg.projectDir` for IDE project directory. When Gradle root differs from IDE project root, do not infer Jugg file location directly from `rootProject.rootDir`.

### 3.2 Key `ModuleInfo` Fields

| Field | Semantics |
|---|---|
| `name` | Canonical module name; Gradle path becomes dotted form. |
| `moduleRootDir` / `projectRootDir` | Module root and IDE project root; relative paths support cross-machine/remote synchronization. |
| `sourceDirs` | Flat set of every effective source root, including KMP common roots. |
| `buildVariant` / `buildPathInfo` | Current variant and inferred AGP output paths. |
| `variants` / `minifyEnabled` | All variants and their actual minify settings. `minifyEnabled` derives from the `variants` entry matching `buildVariant`; `null` means an old snapshot or AGP did not expose this setting. |
| `moduleDependencies` / `runtimeModuleDependencies` / `libraryDependencies` / `runtimeLibraryDependencies` | Compilation, APK-runtime ownership, and library dependencies. `runtimeModuleDependencies=null` denotes an old snapshot and retains legacy module-dependency traversal. |
| `applicationId` / `namespace` | Basis for APK ownership, Manifest, and androidTest target resolution. |
| `isUseDataBinding` | DataBinding build feature read from Gradle; must survive merge to choose DataBinding mode for incremental layout compilation. |
| `instrumentationTargetPackage` | Nonempty on a synthetic androidTest module. |
| `kaptDependencies` / `kspDependencies` / `kotlinPlugins` | Annotation-processing and Kotlin-compiler inputs. |
| `kotlinJvmTarget` / `kotlinFreeCompilerArgs` / `kotlinPluginOptions` | Effective JVM target, extra compiler arguments, and Gradle subplugin arguments for the Kotlin compilation task. `kotlinFreeCompilerArgs` includes `-opt-in=<marker>` converted from typed `compilerOptions.optIn`. |
| `kotlinCommonSourceDirs` | Kotlin source roots the selected Android Kotlin compilation treats as common; empty for non-KMP or failed reads. |
| `kotlinFragmentSourceDirs` | Fragment-to-source-root map exposed by the selected Android Kotlin task; empty map for old/unsupported snapshots. |
| `kotlinFragmentRefines` | Fragment-refinement edges: key is refining fragment, value its direct refined fragments. |
| `externalBuildInfos` | Current-variant Flutter/C++ external-build types; `inputDirs` (each `ExternalBuildInputDir` has recursive trigger root plus accepted `ExternalBuildInputFilterRule` set), `configFiles` inputs, `excludedDirs` generated/cache paths never watched, Gradle task producing final native output, native output location, and Flutter-assets output directory. Native output is one `File` dispatched at runtime as archive or directory, not separately modeled container types. Old `inputDirs` string arrays are rejected explicitly at read boundary; a full Gradle build rewrites the snapshot. |
| `kotlinDefaultFragmentName` | Task-default fragment used without exact source-root match; `null` for old/unsupported snapshots. |
| `composeResourceInfo` | Detected Compose-resource task metadata, including supported/unsupported status and reason. Incremental flow consumes task/generator API structure rather than exact Kotlin/Compose version filters. |

`JuggProjectInfo.agpR8Classpath` is a root-project field. Gradle init script loads `com.android.tools.r8.D8` from the actual Android plugin classloader and reads its code source. If that path lies in Gradle `jars-*` / `transforms-*` instrumentation cache, recover the original same-name artifact from Android-module or root-project buildscript classpath. If no original artifact exists, leave the field `null`; Dex stage uses bundled Jugg R8 rather than exporting an instrumentation artifact dependent on Gradle-private classes. Jugg does not copy the R8 distribution. IDE/CLI injects only the path into in-memory compile context, not `FullBuildInfo` or `compile_context.db`. On composite-build merge, prefer the path from the Gradle snapshot owning the final Application module so an included build's AGP R8 does not override the main app.

Read `kotlinJvmTarget` and `kotlinFreeCompilerArgs` preferentially from current-variant Kotlin task `compilerOptions` for Kotlin 2.x typed options. Convert markers from typed `compilerOptions.optIn` into `-opt-in=<marker>` in original order; fall back to old `kotlinOptions` only for older Kotlin Gradle Plugin. Read `kotlinPluginOptions` from task `KotlinCompilerPluginData.options.arguments`; consume current compilation first and use the nearest parent module only if arguments are empty. Never merge option sets from several compilations. Kotlin task discovery supports AGP 9 Built-in Kotlin and KMP Android `compileAndroidMain`.

Read `kotlinCommonSourceDirs` from `commonSourceSet` structure on `compile<Variant>Kotlin` / `compile<Variant>KotlinAndroid`, retaining direct common roots, intermediate `sharedMain` roots, and task-configured generated common roots. For K2, also read fragment sources, refinement edges, and default fragment from `multiplatformStructure`. Neither source-set names nor `src/<name>` paths are used for guesses. Gradle reader adds these roots to `sourceDirs` too. Merge output ensures common roots are a subset of `sourceDirs` and preserves the authoritative Gradle fragment graph; flat IDE `sourceDirs` must not override those identities.

`ComposeResourceInfo.resourceDirectories` is not guessed from a fixed `src/<sourceSet>/composeResources` path. `GradleProjectInfoReader` reads Compose task `fileSuffix` and `originalResourcesDir`, so default and Gradle-DSL custom directories enter project info even before they exist. It also stores support status/reason, generator classpath, package name, accessor visibility, and packaging/asset relative paths for serialized file-change recognition and incremental compilation.

`ModuleBuildPathInfo.composeResourceGeneratedSourcePath` derives the Compose generated-source path from `generatedSourcePath`, not from persisted Gradle-task `codeDir`. After incremental generation, `ComposeResourceCompiler` writes accessors directly there so Android Studio indexes new resource references. `allBuildPaths` already contains parent `generatedSourcePath`; do not add the child directory redundantly.

`ModuleBuildPathInfo.buildDirRelativePath` records a module's actual Gradle build directory relative to IDE project root. Gradle init script reads it from `project.layout.buildDirectory`; IDE reads Android model build folder, with Gradle value winning on merge. Constructing `ModuleBuildPathInfo` must supply the field explicitly. An explicit empty string means compatibility with an old snapshot and continues using `${moduleRootDir}/build`. Derive classpath, Manifest, mapping, APK/androidTest backfill, and remote-sync paths from this build directory; do not assume outputs sit under module directory.

Kotlin class outputs choose the newest existing result among AGP 9 Built-in Kotlin, KMP Android target, and legacy Android Kotlin directories. Standard KMP Android output `classes/kotlin/android/main` enters both local classpath and remote build-output sync, preventing IDE virtual `androidMain` dependencies from existing while actual commonMain/Android classes remain unresolved.

Project-info `sourceDirs` may retain generated source under build directory because Kotlin/KMP compile context may need those roots. Do not remove them during project-info merge. Remote-build compile context maps `buildPathInfo.projectRootDir/moduleRootDir` to local classpath-backup directories, so file-change entry cannot treat `buildPathInfo.buildDir` as local output. `FileChangesHandler` reconstructs actual local build directory from `ModuleInfo.projectRootDir/moduleRootDir + buildDirRelativePath`, also excluding traditional `${moduleRootDir}/build`, and prunes changed files and directory recursion. Centralized build directory need not lie within module root.

The `compile_context.db/module_builds.json` writer stays at version 2; reader accepts versions 1 and 2. Restore an absent `buildDirRelativePath` in version 1 as empty string, so users retaining old `complete_flag` do not need a full rebuild. Version 2 preserves normal default/custom paths, while a damaged version-2 record missing the field also falls back to traditional directory. If `complete_flag` itself is missing, do not repair automatically; a successful Jugg full build still must rebuild context.

A synthetic androidTest module is named `${module.name}.androidTest`, fixes `buildVariant` to `debugAndroidTest`, and is marked by `instrumentationTargetPackage`. When IDE project info is created, it uses test and target package data from IDE Android model exposed by `AsDeployerCompat#getIdeModuleInfo`. In library self-targeting cases, Chipmunk / Narwhal feature / Otter / Panda inheritance chain falls back to `selectedBasicVariant.testApplicationId`, `androidProject.testNamespace`, or `${androidProject.namespace}.test`. Mark IDE `.androidTest` as androidTest module only when both test and target package are valid; treat `uninitialized.application.id` as invalid. If Gradle project info exists, require the IDE `.androidTest` synthetic module to occur in Gradle's androidTest module set too. Without a Gradle snapshot, instead require Java/Kotlin source under a source root. During Gradle merge, nonempty Gradle test fields still take priority and IDE-only androidTest modules are dropped.

### 3.3 Effective Model

IDEA uses `IdeaProjectModelSource` for “IDE model + Gradle model.” Standalone and IDE-free modes use `GradleProjectModelSource` to merge root and included-build Gradle snapshots directly, without fabricating empty IDE project info. `BuildTarget.APP` excludes Gradle-only androidTest modules; `BuildTarget.ANDROID_TEST` includes them.

`CompileContextManager` retains a source model and applies module custom classpath in memory to produce the effective model. No production consumer currently relies on cross-Runtime model identity, so no additional fingerprint/generation state is persisted. When IDEA/standalone recovers Compile Context after a Runtime-owner switch, it must reload the source model from Gradle snapshots first, avoiding stale in-process modules/dependencies from another Runtime's earlier full build.

`CliRunConfigurationGenerator` also consumes effective Gradle project info: prefer the latest successful configuration, then application module named `app`, then stable order by module path/name. Use `buildVariant`, defaulting to `debug`. Generate default UUID deterministically from module path + variant. Infer APK directory of flavor `Debug` / `Release` variants as `<flavor>/<buildType>`. After Gradle succeeds, write actual compile options back into current configuration so defaults do not remain authoritative indefinitely.

## 4. Core Call Chain

### 4.1 Reading Gradle Project Info

```text
IDE / Gradle compilation triggers project-info update
  -> GradleProjectInfoLocalFetchManager or Gradle compile client assembles init-script arguments
  -> readProjectInfo.gradle.kts
     embeds GradleProjectInfoReaderManager / GradleProjectInfoReader logic
  -> GradleProjectInfoReaderManager.readAndSave()
     read environment, AGP R8 code source, previous project info, current Gradle project info
  -> GradleProjectInfoReader.getProjectInfo()
     traverse subprojects and read Android/Java modules, variants, source sets, classpaths, dependencies
     read Kotlin common roots from selected Android Kotlin task commonSourceSet
     read fragment roots, refinement edges, default fragment from K2 multiplatformStructure
     validate Compose-resource tasks and read generator/resource-directory metadata
     read current-variant Flutter compile/pack Jar tasks, mergeNativeLibs task, external source roots, output directories, native archive
  -> write gradle_project_infos.json
     for configured Application/Dynamic Feature, write selected-variant strip configuration to classpath/native_strip
     for included builds, additionally write gradle_include_builds.txt
```

Classes under `main/src/main/java/.../gradle/script` also serve as source templates for the generated init script. Investigations must consider both the production wrapper and embedded result in `main/src/main/resources/gradle/readProjectInfo.gradle.kts`.

The init script is meant to obtain build-side facts without modifying a project's `build.gradle`, not to replace IDE model. IDE model better supplies module/source structure and current IDE selection; actual tasks, variants, classpaths, dependencies, annotation-processor parameters, Compose-task metadata, and custom build directories are more reliable in Gradle's execution environment. `JuggProjectInfoMerger` joins both rather than assuming either is always complete. `-I readProjectInfo.gradle.kts` is an extra input for one build invocation, requiring no Jugg Gradle plugin and writing no reader logic into user scripts.

For Application and Dynamic Feature APK ownership, use Gradle's resolved variant runtime classpath. `GradleProjectInfoReader` collects project components from this and composite builds through `ProjectComponentIdentifier`. Gradle DSL exclusions, substitution, and variant selection have already taken effect. `ModuleApkBelongsUtils` uses this flat resolved-module set directly instead of recursively inferring ownership from IDE/compile dependencies. If reading fails, target runtime configuration is absent, or old JSON lacks `runtimeModuleDependencies`, retain `null` and fall back entirely to existing `moduleDependencies` traversal. Do not serialize “unknown” as an authoritative empty set.

Application and Dynamic Feature also read external libraries visible in the final APK from selected variant `RuntimeClasspath` into `runtimeLibraryDependencies`. Other modules keep existing compile-dependency reads so each Library does not resolve runtime graph again. This path consumes only library artifacts, so `doGetDependencies` skips legacy `ResolvedConfiguration` traversal in `getProjectDependencies`: that traversal yields only discarded `ModuleDependency` while resolving the entire APK-root runtime-artifact graph (about 16–18 seconds per APK-root module in multi-Dynamic-Feature projects). `getRuntimeModuleDependencies` reads runtime module dependencies separately through `resolutionResult`; neither source replaces the other's data or failure semantics. Dependency diffs first inspect the full-build baseline. If baseline has nonempty runtime-library data, both diffs compare `libraryDependencies + runtimeLibraryDependencies` with deduplication by absolute artifact path. With empty baseline runtime data, both compare only `libraryDependencies`. Thus a new baseline detects AAR/JAR entering APK only through Maven runtime scope, `runtimeOnly`, or other runtime transitives, while an old baseline does not misreport every newly collected runtime library after upgrade. Missing or failed runtime-configuration resolution for an APK-root module means an incomplete dependency snapshot: fail this Gradle read and fall back to full build, rather than saving an authoritative empty list and deploying.

`readProjectInfo.gradle.kts` branches after `gradle.taskGraph.whenReady`. A dry run still calls `readAndSave()` immediately because no real task executes. Otherwise attach the read to `doLast` on the task graph's final task so dependency snapshot is taken as far as possible in execution phase, reducing configuration-time resolution warnings in Gradle 9/newer AGP.

For old AGP, prefer `applicationVariants` and `libraryVariants` (Dynamic Feature uses `applicationVariants`). Only when legacy API returns no variants use names/effective `minSdk` collected during configuration from `androidComponents.onVariants`. Store results by Gradle project path in root-project extra properties without retaining AGP variant instances. The same fallback data supplies project-info `buildVariant` inference and AndroidTest assemble-task injection. Register for application, library, and dynamic-feature plugins. If reflective registration fails, continue the old path without breaking Gradle configuration.

Read `Variant.minSdkVersion` from `mergedFlavor.minSdkVersion.apiLevel` under old API or `minSdk.apiLevel` under Android Components. Once `buildVariant` is selected, put its value in `ModuleInfo.minSdkVersion`, falling back to `defaultConfig.minSdkVersion` only when unavailable. A later copy must not overwrite it with defaultConfig or D8 uses the wrong API level when a flavor overrides minSdk. Old snapshots lacking nullable variant fields keep original module minSdk/signing config without migration; refreshed Gradle info captures effective variant values.

Each variant record also captures actual minify configuration for `ICompileContext.isMinified`. A legacy variant may not expose it directly: try `variant.isMinifyEnabled`, then `variant.buildType.isMinifyEnabled` on stable `com.android.builder.model.BuildType`. Under Android Components read `com.android.build.api.variant.CanMinifyCode.isMinifyEnabled` from variant implementation. Both are best-effort; if unreadable, leave `null`, and `ICompileContext.isMinified` treats it as not enabled. Do not infer minify from whether `outputs/mapping/<variant>/mapping.txt` exists: an old mapping can remain after users disable minify, misclassifying unminified output.

When one task graph contains several variants, `guessBuildVariant()` first matches the longest variant name exactly against Gradle launch-task suffix, then uses the existing Debug/Release fallback. For instance Flutter add-to-app `profile { initWith debug }` may run both Debug and Profile tasks, but `:app:assembleProfile` must select Profile to read `compileFlutterBuildProfile` and `mergeProfileNativeLibs` metadata.

Composite builds use a conditional path. Ordinary projects continue reading only through existing `taskGraph.whenReady`. Only when root build finds nonempty `gradle.includedBuilds` does it add lightweight `:juggReadProjectInfo` tasks in each included build as dependencies of requested tasks. Each included build then enters its own task graph and writes `gradle_project_infos.json` under its own project directory; root copies these into the main project's database directory. Continue using `jugg.projectDir` for shared relative-path calculation, never to override an included build's snapshot output directory.

If reading or file generation in an included build still fails, aggregation must not stop the root-project snapshot. Retain and list an old copy when it exists; skip only a build with no previously successful copy. A later successful read replaces the old copy.

Register Application runtime injection immediately after the Android application plugin loads using `androidComponents.onVariants`. AGP with `runtimeConfiguration` adds `jugg-runtime.jar` to the specific variant; older versions or reflection failures fall back to generic `runtimeOnly`. Failure of this extra path must not interrupt Gradle configuration.

A minified buildType additionally gets `build/jugg/proguard-rules.pro` from `GradleApplicationInjector` via `proguardFile()`. Besides keeping Application subclasses, it needs `-dontwarn` for types referenced by injected runtime but neither packaged nor supplied by host: private Kotlin runtime `...runtime.kotlin.Metadata`, `...runtime.kotlin.jvm.JvmStatic`, `...runtime.kotlin.jvm.internal.markers.KMappedMarker`, and unrelocated `org.jetbrains.annotations.NotNull` / `Nullable`. R8 fails on missing classes for Java-only apps or apps without annotations dependency. Recheck these rules after changing preprocessed Dragonfly JAR; Debug skips R8 and cannot cover this path.

Compose metadata is gated by strict structure. With no `org.jetbrains.compose`, `composeResourceInfo=null`. Legacy pipeline requires one `GenerateResClassTask` and required properties; modern pipeline requires a mutually consistent converter/accessor/collector task set and properties. Once plugin is detected, save `Unsupported`, a user-visible reason, and any readable configured roots even if task metadata or generator API shape is unsupported, so resource changes do not vanish silently. Reading saves configuration only; it neither executes Compose tasks nor guesses capability from exact Kotlin/Compose versions.

External-build info follows current-variant real Gradle tasks, uniformly representing the task that produces final native output plus its location as one `File` dispatched at runtime as file or directory. For Flutter, find `compileFlutterBuild<Variant>`, then choose native task by Flutter version: older versions use the unique `Jar` task `packJniLibsflutterBuild<Variant>` or `packLibsflutterBuild<Variant>` dependent on compile task, taking native output from `archiveFile` / `archivePath`. Flutter 3.x uses dependent `copyJniLibsflutterBuild<Variant>` and its real `destinationDir`, never a guessed fixed `generated/jniLibs` path. Flutter also records project root and assets output directory because Dart incremental builds must deliver `flutter_assets`. C++ native output is actual directory of `merge<Variant>NativeLibs`; assets output is empty. Gradle snapshot supplies configuration facts; the task executes only when corresponding Dart/C/C++ files enter incremental compilation. Serialize fields into Gradle JSON and let them override empty IDE values during merge.

### 4.2 Merging into Compile Context After Sync

```text
JuggManager.onSyncEvent()
  -> updateProjectInfo()
  -> CompileContextManager.updateCompileContext()
  -> IdeaProjectModelSource
     create IDE project info; mark IDE androidTest modules using complete IDE Android-model androidTest artifact data
  -> JuggProjectInfoMerger
     merge IDE, Gradle, and included-build project info
     on same-name Application path conflict, use that Application only when primary Gradle snapshot contains real R.jar
  -> CompileContextManager
     apply custom classpath and update effective model / Compile Context
  -> JuggManager.rebindCompileContext()
     bind DeployFileManager / JuggCompiler / FileChangesHandler / FileChangeManager(GitFileChangesDetector) / CustomCompilerManager to new context
```

Project-snapshot update does more than replace JSON. It affects classpath, module-to-APK ownership, file-change filtering, custom compilers, dependency-change confirmation, and deployment-history recovery.

Final merged `JuggProjectInfo` / `ModuleInfo` from `JuggProjectInfoMerger` lives in compile-context memory, not rewritten into `project_infos.json`. On disk, `project_infos.json`, `gradle_project_infos.json`, and included-build snapshots are distinct inputs. Neither one file's timestamp nor fields alone describe the final merged state; inspect all inputs and compile logs for final behavior.

`ModuleInfo.externalBuildInfos` stores recursive Flutter/C++ trigger roots and file-type rules, configuration inputs, excluded directories, current-variant tasks, native output location, and Flutter-assets output directory. Each trigger root carries a `filterRules` set (`Dart`, `FlutterAsset`, `CppSource`, `CppHeader`, `NativeDirectory`). Rules are OR-ed; an empty set is invalid. Flutter input roots comprise Flutter package root and parents of Dart files in `compileFlutterBuild<Variant>.sourceFiles` (`Dart`). Local pub package roots found by walking task inputs use the same rule. Non-Dart task inputs create a `FlutterAsset` directory only strictly below their package root; package root itself always creates `Dart` only. `pubspec.yaml`, `pubspec.lock`, and `l10n.yaml` become `configFiles`. Directory entries in `flutter.assets` and `arb-dir` in `l10n.yaml` create `FlutterAsset` directories; single-file assets, fonts, and shaders rely on task inputs. Declared paths must remain under their package root without symlinks or `excludedDirs`. Native input roots come from externalNativeBuild configuration roots (`CppSource + CppHeader`), parent directories of non-Header sources from CMake File API / `android_gradle_build.json` (`NativeDirectory`), and parents of explicit Header sources plus include roots (`CppHeader`). Resolve relative CMake target source paths against codemodel `paths.source`. When a parent equals the configuration root, do not broaden its rules. Ignore unidentified metadata inputs or ones that cannot fit `NativeDirectory`, emitting one aggregated debug log per external build without setting `unsupportedReason` or writing them into project info. After collection, only normalize and deduplicate identical path + rule-set pairs; retain parent/child paths and same-path entries with different rule sets. Never watch Flutter SDK root, pub cache root, `.dart_tool`, Gradle user directory, Android SDK/NDK/CMake toolchain, staging, or module build directory: these enter `excludedDirs`. If input roots are identifiable but tasks, assets output, or native output cannot be read, retain the record and mark `unsupportedReason`; Run preflight chooses a full Gradle build.

After an external task succeeds, do not start an asynchronous full local project-info fetch. The derived Gradle command executes `juggCollectExternalBuildInfo` with init script and invocation parameters, rereading metadata only for this run's module/variant/type into a temporary directory. After validating completeness, runtime uses old task path as locator to replace the corresponding record in the latest Gradle snapshot, saves atomically, and reuses normal project-info merge. `BaseCompileContext.update()` dispatches module updates and `FileChangesHandler` atomically replaces scan roots/exclusions immediately. Failure of collector, targeted merge, or context writeback fails external compilation, avoiding successful tasks followed by stale monitoring. `request.json` is a temporary per-invocation execution/collection manifest created by `ExternalBuildTaskRunner`, containing invocation ID and module/variant/task/type—not persistent project configuration or an independent read-only metadata request. Production derived commands require nonempty external task path and always run external task(s) and collector in one Gradle invocation. There is no product entry for collector-only requests; separate collector tests verify dependency orchestration. C++ requests additionally carry APK owner's (base app or dynamic feature) module root and variant. Collector reads that owner's `strip<Variant>DebugSymbols` configuration (`keepDebugSymbols` and per-ABI strip executable), reproduces AGP's single-file strip semantics in this invocation directory, and writes stripped output path as result `strippedNativeOutput`. This describes this invocation only and does not enter `ExternalBuildInfo` / `ModuleInfo`. Collector neither runs APK owner's strip task nor resolves its input artifact provider, so unrelated app strip/merge tasks do not reenter the graph. During root-project evaluation (`gradle.rootProject`), collector binds local-request module tasks with `dependsOn`, ensuring under Configuration on Demand and parallel builds that native/Flutter outputs finish before metadata is read/stripped. `mustRunAfter` or observing `TaskState` alone is not a completion barrier. Result still checks valid output, invocation ID, and exact request/update key; these are completeness gates, not ordering checks. A legacy request/result JSON without APK owner or stripped output causes an explicit failure for this C++ run, never fabricated success.

After a full build, if IDE does not reliably report Sync Success, Jugg compensates by reading IDE project info once. That branch uses IDE data only for module/source structure; library dependencies remain authoritative from Gradle project info produced by the same full build, independent of IDE JSON mtime changes. Normal IDE Sync retains its existing mtime freshness judgment.

### 4.3 Standalone Daemon Project Registration

```text
jugg CLI sees target project has no owner
  -> prefer any running standalone Runtime
  -> if none, start jugg-standalone --project-dir <projectDir> under global launch lock
  -> JuggDaemon
     create StandaloneProjectRegistry
     invoke StandaloneJuggRuntimeAssembler for startup project
  -> first valid project-scoped MCP request
     validate tool, arguments, and projectDir
     if unregistered, invoke StandaloneJuggRuntimeAssembler
  -> StandaloneProjectRuntime
     record runtime.owner.json / owner-change event under project lock
     create project McpToolInvoker
  -> McpLocalServer
     route version / list-projects through global Runtime metadata
     route compile / deploy / gradle-build / status / restart / devices by projectDir
```

Global requests such as `version` and `list-projects` do not register a project. Invalid tools/schemas or nonexistent project directories have no registration side effect either. Initialization is coordinated independently by canonical projectDir: concurrent requests for one project share one initialization, while different projects initialize in parallel and a slow project cannot block requests to already registered ones. On constructor failure, close that project's created monitors, scope, task manager, and logging resources symmetrically, then return `PROJECT_NOT_INITIALIZED`. Registered projects continue; failed projects may retry safely. If target project is not yet in `list-projects`, CLI retains pending projectDir, and the first project request waits for automatic initialization under the standalone startup heartbeat.

`jugg stop` bypasses this MCP routing. CLI synchronously invokes the stable standalone launcher with `--stop-all`. Before loading active Runtime JARs, bootstrap matches all `StandaloneBootstrap` processes under the same Jugg root via `ProcessHandle`. On platforms supporting graceful termination, request it first and force termination if still alive after 5 seconds; on others force termination directly. This handles a startup stuck before the port is ready without stopping IDEA Runtime, processes under other Jugg roots, or deleting persistent project state.

Step 11 has `StandaloneProjectServices` assemble Gradle-only model, Compile Context, history recovery, WatchService/Git reconciliation, and shared `JuggCompilerHelper` / `JuggDeployerHelper`. WatchService prefers JDK `FILE_TREE` to register one native recursive WatchKey at project root, falling back to per-directory registration when unsupported. Both ignore `.git`, `.gradle`, `.idea`, and `build` subtree events. If startup fails, for example due to file handles, close partially created watcher, register Git listener, and immediately refresh Git. Later `status`, `compile`, and `deploy` continue using Git refresh for changes. Process capabilities are `version`, `list-projects`, `compile`, `deploy`, `gradle-build`, `get-compile-status`, `status`, `restart`, `report-prepare`, `report-upload`, and `devices`. The first build command creates the current profile on demand from Gradle project info. `gradle-build` establishes baseline then installs or deploys; `deploy` performs ordinary incremental compilation and deployment. Without serial, `restart` restarts all online target devices. `devices` lists online devices through project `IDeployTargetManager`. With a remote current profile, standalone full Gradle build/fallback reuses IDEA's `RemoteGradleCompileClient`, SSH/iFT connection, file sync, and artifact fetch. `rsync` and iFT remain external tools required on the standalone host. Incremental compilation, device operations, and the pre-remote-build project-info Gradle dry run still execute locally. Standalone has no authentication dialog; SSH credentials or iFT authentication must be preconfigured, otherwise the compile job returns failed, cleans terminal output/cancellation listener, and gives a noninteractive-authentication hint. Runtime construction's config/history/context recovery and each full compile/deploy chain hold the same project write lock; standalone project write transactions count as daemon activity. Idle `status` obtains project lock nonblockingly before owner recovery, Git refresh, and consistent snapshot. If this Runtime is compiling or another write transaction holds the lock, return current real read-only snapshot immediately, without refreshing or writing file state. After detecting an IDEA/standalone owner change at runtime, the next business chain or status snapshot that successfully takes the project lock reloads Compile Context, history, APK, and Git file state and invalidates deployment memory cache before starting.

Project Runtime Lock expresses ownership between Runtimes such as IDEA, standalone, and CI; it does not serialize tasks within one Runtime. On a `TaskRunnerManager`'s first project transaction it acquires an NIO file lock; subsequent cross-thread project tasks share the lease with a reference count until the last finishes. `RuntimeTaskCoordinator` handles same-Runtime exclusion: independent project transactions have separate logical owners and run serially. Child tasks submitted within a transaction through `runTaskSafe`, `runBackgroundSafe`, or `runAsyncSafe` inherit their parent's owner automatically and join across threads without waiting for the parent. Another Runtime waits until all references to the current Runtime's lease end. Only when contention occurs does a waiter log debug `Runtime lock contention` with waiting Runtime, owner Runtime/PID/command/jobId, and eventual wait duration; uncontended locks do not log.

Global Resource Lock protects only small read-modify-write commits of shared resources under `~/.jugg`; it is no longer a TaskRunner task type. `TaskRunnerManager` exposes neither `isGlobalWrite` nor arbitrary global callbacks. Concrete owners of settings, hot update, CLI/skills, runtime resources, and global history acquire `~/.jugg/locks/global.lock` internally. A Global Lock action must complete synchronously and only do bounded local resource reads/writes. It must not launch async tasks, call back into IDEA/business logic, acquire business monitors, or wait for network, external processes, threads, or Futures. Lock order is Project Runtime Lock → Global Resource Lock. While current thread holds G, both blocking and try acquisition of Project Lock fail immediately, keeping G a leaf of the wait graph. Hot update uses “two-phase prepare + short commit”: a first short lock snapshots reusable cache/metadata baseline, download and verification occur outside the lock, and a final short lock rechecks baseline before atomic publication. Other global-resource owners can commit during downloads; a slower stale update cannot replace a newer committed update. Windows CLI installation publishes `~/.jugg/bin` files under G only. After release, it invokes `reg.exe` to update user PATH with a hard five-second timeout so a stuck child cannot hold G.

The fixed order is Runtime logical owner → Project Runtime lease. Coordinator reference-counts each owner; reentry by the same owner increments references without a wait edge, so a parent waiting for its child cannot have that child wait back on the parent. Nonblocking Host tasks without a parent owner retain previous concurrency semantics; other independent project transactions remain serial. Existing callers such as deployment cache need no extra local locks. `status` checks coordinator and Project Runtime lease idle state using nonblocking `try`; on failure it returns read-only snapshot immediately. Callers declare task attributes without deciding whether they are top-level or children.

Runtime disposal does not forcibly alter owner or Project Runtime lease reference counts. The acquiring tasks release locks naturally in `finally`. If a lock-holding task depends on async completion, the completion owner must end waiting with a cancellation result from `close()`; caller then exits its transaction promptly. `GradleProjectInfoLocalFetchManager` therefore completes an active remote-init completion during close, and `JuggManager` does not continue classpath initialization. This avoids retaining project lease forever when the platform discards queued Host tasks after IDEA project closure.

`IExecutionLockManager` only declares project-lock and owner-read operations, with no default method implementations. Concrete Runtimes or tests must explicitly implement waiting/nonblocking lock acquisition, project-state snapshots, and unsupported capabilities so new Hosts cannot silently inherit wrong concurrency or capability semantics.

Only external MCP requests refresh daemon idle deadline; WatchService, background polling, and update checks do not. At four hours, if compile/deploy/Gradle jobs, project write transactions, or update downloads remain, recheck every minute. Once clear, stop MCP Server and dispose all project Runtimes. Users can also run `jugg stop` to terminate every standalone daemon under the same Jugg root. Platforms with graceful termination use JVM shutdown hook first and force termination on timeout; Windows or other platforms without graceful termination force it directly.

## 5. Gradle Compile-Client Boundaries

| Class | Boundary |
|---|---|
| `LocalGradleCompileClient` | Runs Gradle locally, collects app/test APKs, reads library Test APK build history, fetches classpath. |
| `RemoteGradleCompileClient` | Runs Gradle remotely, downloads outputs/logs/diffs, and handles differences in remote project paths. |
| `CopyGeneratedSourceHelper` | After remote Gradle compilation, writes generated/custom-sync artifacts from classpath backup to local module build directories. |
| `SshCommand` | Constructs remote Gradle arguments including `jugg.diffMode`, `jugg.incDeployTimes`, and `jugg.libraryTestTasks`. |
| `ApkLookupPlanner` / `FindOutputCommand` | Locates output artifacts under required/optional APK rules. |
| `GradleDependencyDiffer` | Produces dependency changes in diff mode so dependency manager can determine user-confirmation needs. |

`RemoteGradleCompileClient.executeRemoteCommand()` reuses SSH authentication, proxy, environment variables, PTY, and cancellation support. It runs one noninteractive command under `remoteProjectPath` in a separate subshell with a unique completion marker. One SSH connection attempt waits at most 30 seconds. This entry does no file sync, APK/classpath fetch, or deployment orchestration, and does not use Gradle commands' 90-second no-output timeout. User command and terminal output enter only separate Run Content; persistent logs contain only command type, connection, and exit result, never command body.

Dependency changes require explicit confirmation. If a build file changed and source changes already exceed the incremental threshold, Jugg first shows Too many changes confirmation and only shows build-file diff when user chooses incremental for this run. Under the threshold, show file diff immediately. User may choose to read dependency changes, ignore build-file changes for this run, fall back to Gradle, or cancel. Only after confirmation are dependency-library artifacts converted into `ChangedFile` for incremental compilation. A build script can change arbitrary build behavior; dependency lists alone cannot prove the rest of APK unchanged. Automatic guessing would present unverified risk as success.

Gradle diff retains two comparison baselines: `diffResult` compares previous-build dependencies to display additions, removals, and upgrades this run. `diffResultWithFull` compares the most recent full-Gradle baseline to determine library files genuinely needing compilation, replacement, or rollback. Library Dex may merge into one APK artifact, so previous incremental results alone cannot establish the old JAR. User choosing “ignore” only accepts that current build-file change does not affect their development flow; Jugg has not verified script equivalence. On anomaly, refresh baseline with full Gradle.

Participation of runtime libraries in dependency diff follows project info saved by the most recent full build, without raising `full_build_info.json` serialization version. If an old full-build baseline has empty `runtimeLibraryDependencies`, retain compile-only dependency diff, preserve existing compile context, and do not force immediate full build. After a successful full Gradle build records nonempty runtime-library baseline, both subsequent diffs include runtime libraries. If the full baseline truly has no runtime external libraries, the first new runtime-only library will not enter this mechanism until after the next full build.

APK lookup starts from Run Configuration output pattern; generated patterns use the actual build folder exposed by IDE Android model. Derive androidTest pattern from `/outputs/apk/`, supporting both `app/build/...` and centralized project-root `build/app/...`. Remote classpath sync uses project-root-relative build-output paths so custom build directories restore to the same local locations.

Rsync filters for remote classpath depend on build-directory type. Ordinary `${moduleRoot}/build` modules share `build/...` rules per variant, avoiding repeated expansion of identical arguments in large multi-module projects. Custom build directories, `customClasspath`, and `customSyncFilePath` retain exact project-root-relative paths so wildcards do not obscure centralized outputs or project configuration.

Before Gradle client starts, `JuggCompilerHelper.gradleCompile()` invokes `GradleWrapperRepairer` only for `compileCommand` using `gradlew` / `gradlew.bat`. If that directory has `gradle/wrapper/gradle-wrapper.properties`, restore missing `gradlew`, `gradlew.bat`, and `gradle/wrapper/gradle-wrapper.jar` from Jugg resources and make `gradlew` executable. Without properties or a wrapper command, do not modify the project. Create missing files only, never overwrite existing files. During remote compilation on a Windows host, before sync convert CRLF to LF in the Unix `gradlew` actually used, writing only on content change. Do not change `gradlew.bat`, other scripts, or Gradle config; purely local compile and remote-result fetch leave originals untouched.

Host platform supplies base environment for local Gradle commands. In IDE use IntelliJ's loaded shell environment so macOS GUI launch does not omit `node` or other user tools from `PATH`; on read failure fall back to IDE process environment. Standalone keeps launcher/shell process environment. IDEA `JAVA_HOME` prefers linked-project Gradle JVM resolved to a real path through IDE JDK resolver, then module Java SDK, then system `JAVA_HOME`. Standalone preserves explicit `JAVA_HOME`, using daemon `java.home` only if absent, so a Java 11 daemon does not force project Gradle onto Java 11. Local project-info dry run before remote compile uses the same environment, retaining IDE Gradle JDK even when an Android module's SDK is not a Java SDK.

Local project-info reads are background maintenance; log their Gradle stdout/stderr at `debug`, never user-visible `warn`. Results still inform context updates through status and return values.

When Gradle project info is deleted for incompatible serialization or read failure, local rebuild remains nonblocking rather than occupying a global initialization state shared by incremental and full Gradle compilation. An existing JSON snapshot means Gradle project info is readable, not that incremental compilation is ready: it also needs `FullBuildInfo.compileCommand`, and any missing-snapshot rebuild must have completed. Set `isRebuildingMissingProjectInfo` only if JSON is absent at startup refresh. With JSON present but no full baseline, do not wait for rebuild or force another remote dry run solely for that reason. Even if Gradle writes JSON early, wait for that missing-snapshot refresh to finish updating compile context before resuming incremental compilation. Paths already known to require a full Gradle compile run directly. For an intended incremental compile, poll for rebuild completion; on rebuild failure fall back to full Gradle, never deploy using only IDE project info.

When a remote build switches compile command, always perform one local project-info dry run with the current command even if local Gradle project info exists. Run this refresh in parallel with remote build and set `shouldWaitForRemoteInit`. After successful remote full build, initialization of incremental compilation reads and clears the flag, waiting for local refresh only if it was set, so ordinary IDE Sync/dependency recovery background refresh does not delay remote flow. Then read project info and fetch classpath to avoid composing sync paths from a stale variant. If classpath fetch fails after remote full build succeeds, do not initialize incremental compilation this run; retain existing compile context and deployment history.

After all APK downloads succeed, `LocalGradleCompileClient` / `RemoteGradleCompileClient` prune `build/jugg/classpath/apk/` files absent from this run's found APK set. On lookup/download failure, retain old cache.

## 6. Hidden Constraints

- Adding a `ModuleInfo` field requires updating `JuggProjectInfoSerialize`, `JuggProjectInfoMerger`, `ProjectInfoSerializerInGradle`, `CmdLineContextManager`, and `LibrariesBackupHelper`, or a Gradle/IDE/CLI path drops it.
- Groovy `JsonBuilder` / Gson serialize `Variant` fields as properties without a manual allowlist. New fields must be nullable with defaults; `null` on an old snapshot means unknown. `ModuleInfo.minifyEnabled` is derived, not stored: Gson does not write it and merger does not merge it. Merger retains Gradle-side `variants`, leaving `minifyEnabled=null` for IDE-only modules.
- Gradle-side Groovy `JsonGenerator` writes Kotlin Boolean `is*` fields under JavaBean names (`isUseDataBinding` → `useDataBinding`). IDE `ProjectInfoSerializer` uses Gson field names, so on load it automatically copies bean names to declared `is*` Boolean fields on `ModuleInfo`; do not add a one-off allowlist for a switch. A new field of this kind should be set true in `gson load of groovy snapshot preserves DataBinding setting` fixture and survive Groovy→Gson readback. Merger retention alone cannot prevent loss during JSON read.
- `LibraryDependency.rPackageName` stores an external AAR's R namespace. `GradleProjectInfoReader` best-effort reads `android-symbol-with-package-name` by Gradle component identifier (first nonempty line of `package-aware-r.txt`). If unsupported by AGP or file absent/empty, leave `null` and let `DependencyDiffResultHelper` fall back to AAR Manifest `package`. This is dependency metadata: do not add it to `LibraryDependencySet` file set or CRC diff. Old snapshots read missing field as `null`; filling metadata must not generate false dependency updates. Gradle snapshot serializes it only on `res` entries, not repeated in Manifest/JAR entries. Serialization and copy paths must retain it, especially the hand-written `libraryConverter` allowlist in `ProjectInfoSerializerInGradle.getJsonGenerator()` and `BaseCompileContext.saveTempLibraries()`.
- Read `runtimeModuleDependencies` only for Application/Dynamic Feature roots. Both nonempty and empty lists are authoritative Gradle resolved runtime; only `null` triggers legacy behavior. Convert `ProjectComponentIdentifier.projectPath` by a dedicated rule removing leading `:` before changing hierarchy separators to dots; use `projectName` for a composite-build root. Do not reuse display-name conversion or heuristic `ResolvedDependency.moduleVersion == unspecified`.
- Read `runtimeLibraryDependencies` only for Application/Dynamic Feature roots. When full-build baseline has nonempty runtime-library data, both dependency diffs merge it with `libraryDependencies` and deduplicate by absolute artifact path. When baseline runtime is empty, both remain compile-only. Do not enable runtime based solely on last snapshot or invalidate all old baselines by bumping `FullBuildInfoSerializer` version.
- `JuggProjectInfo.agpR8Classpath` stores only a directly referenced path usable outside Gradle classloader. Do not copy R8 into classpath backup or persist it in `FullBuildInfo` / compile-context disk format. If original buildscript artifact for a Gradle-instrumented code source is absent, or an old project-info lacks this field, treat it as `null` and let Dex stage use bundled Jugg R8.
- `JuggProjectInfo.agpR8Classpath` is nullable, but its constructor parameter has no default. Every construction site must pass existing path or explicit `null`. Code that only changes modules must call `projectInfo.copy(modules = ...)`, never reconstruct root snapshot and lose a project-level field.
- `composeResourceInfo` follows the chain above and Gradle value takes priority in merger; `main/src/main/resources/gradle/readProjectInfo.gradle.kts` must match its generated `gradle/script` sources too.
- Validate element shape of `ExternalBuildInfo.inputDirs` at read boundary. Gradle (Groovy/JsonSlurper) and IDE (Gson) accept only `{directory, filterRules}` objects. String arrays, absent `inputDirs`, or empty rule sets fail as incompatible schema. Existing project-info read boundary records `EXTERNAL_BUILD_INPUT_SCHEMA_ERROR` and drops snapshot, with CLI covered by `ProjectInfoSerializer`. Do not bump `JuggProjectInfoSerialize.VERSION` or recover from old `sourceDirs`/`inputFiles`. In `compactInputDirs`, write directories sorted by normalized path and rules in enum declaration order for stable snapshots.
- `ExternalBuildInfo` retains one native-output field; do not split by archive/directory container. Synchronize it through `ProjectInfoSerializerInGradle.parseExternalBuildInfos`, `ProjectInfoSerializer.restoreExternalBuildOutputs`, and path relocation in `CmdLineContextManager`. Both Gradle/Groovy and IDE/Gson read paths deterministically recover old snapshots at their boundaries: old Flutter `outputDir` means assets output, `nativeLibsArchive` or a prior local version's `nativeLibsDir` means native output, and old C++ `outputDir` means native output. Do not delete database, raise serialization version, or drop fields. `isSupported` requires both assets and native outputs for Flutter, only native output for C++. Flutter 3.x copy task is an AGP `addGeneratedSourceDirectory` output task; reader uses only its `destinationDir` and dependency on `compileFlutterBuild<Variant>`, not bare Flutter intermediate directories outside `intermediateDir`.
- `buildReadProjectInfoScript.gradle` must collect every non-Gradle classpath dependency of embedded init-script sources, sorted by declared dependencies. When `JuggPathManager` references `JuggGlobalPathManager`, include both with the latter first or standalone generated KTS compilation fails.
- `build/jugg/classpath/native_strip` is a migratable full-build toolchain baseline, not a runtime-state DB. A full Gradle build writes APK-owner `keepDebugSymbols` and ABI strip tools keyed by normalized `moduleRootDir + variant`, copying tools into `tools/` with executable properties retained. Write tools before atomically publishing `config.json`; then best-effort clean unreferenced old tools. Reads prefer baseline-copied `backupPath`, using `sourcePath` only for local fallback and diagnostics. CI copying a baseline must include the full `native_strip/` directory (add to allowlist if only `classpath/root`, `apk`, `libraries`, `embedded_apk` are copied) with attributes preserved; a backup tool without executable bit is unusable. This cache is outside `Variant` / `ModuleInfo` / `ExternalBuildInfo` serialization. `Clear Jugg Build` naturally removes it with `build/jugg`, without a new cleanup entry.
- Trailing-comma cleanup has two passes: remove a comma before `)` while preserving `) {` and end-of-line comments; then remove an outer trailing comma left as `),\n)` by nested calls, without removing a nonfinal argument separator such as `),\nnextArg`. Otherwise Gradle 5/6 (Kotlin DSL language version < 1.4) fails script compilation on residual `arg),`.
- `main/buildReadProjectInfoScript.gradle` also adapts source before assembling the injected `.kts`: it extracts selected companion members to top level and rewrites their qualified calls, then rewrites cross-inner-class constructor calls to top-level factories before appending those factory definitions. The order is intentional: rewriting after factory insertion would rewrite the factories themselves. These adaptations avoid script-inner-class compilation/runtime failures on older Gradle Kotlin backends; do not simplify them based only on a newer Gradle run.
- When changing inputs to `buildReadProjectInfoScript` (`gradle/script/**`, embedded `project/info/**`, `DependencyDiffResult`, or generator itself), verification must include generated-script **syntax** regression, not only Gradle 7/9 functional compatibility. Run `ReadProjectInfoScriptContentTest` by default, including trailing-comma contract. With a suitable JDK, also run `ReadProjectInfoGradle5CompatTest` / `ReadProjectInfoGradle6CompatTest`. Gradle 7+ accepts trailing commas; testing 7/9 does not establish older syntax compatibility. See owner/details in `06_testing.md` §7.4.
- Project info records only the fragment graph exposed by the selected Android Kotlin task for this run's incremental compilation. It does not build a full Kotlin source-set dependency graph for all project targets or record deletion graph/generated-source cache.
- `ModuleBuildPathInfo` is the AGP-path compatibility layer; do not scatter hard-coded `build/intermediates/...` paths through compilers.
- Preserve `ModuleBuildPathInfo.buildDirRelativePath` through Gradle JSON, IDE project info, compile-context merge, classpath backup, and deployment-history serialization. On shape changes, first ask whether old values can be migrated deterministically rather than merely bumping compile-context version and forcing a full rebuild.
- Remote classpath filters must not grow linearly with ordinary module count. Deduplicate ordinary `${moduleRoot}/build` output by variant; keep custom build directories and configuration paths exact.
- `ModuleBuildPathInfo.allBuildPathRelative` includes current variant `intermediates/data_binding_artifact` so remote Gradle outputs such as DataBinding setter store return locally.
- `ModuleBuildPathInfo` separates Gradle R.jar into two semantically incomparable sets: application aggregate (`rFilePathCandidates`: `compile_and_runtime_r_class_jar` / `compile_and_runtime_not_namespaced_r_class_jar`) and module compile (`moduleCompileRFileCandidates`: AGP 7.4+ `compile_r_class_jar` and legacy `compile_only_not_namespaced_r_class_jar`). Within each set, select newest `lastModifiedTime` among existing candidates; preserve declaration order on mtime tie. `BaseCompileContext` logs debug with multiple candidates. If no real module-compile candidate exists, `moduleCompileRFile` is `null`; do not invent a modern path.
- `ModuleBuildPathInfo.allClassPath` contains only ordinary Gradle outputs of the module, never any Gradle R.jar. `BaseCompileContext` chooses and appends an R provider by module identity so one module does not expose both modern and legacy R layouts. Synthetic androidTest is modeled as `Library` but must use its own test-variant aggregate R, not the owner module's main-variant R. `allBuildPaths` contains both aggregate directories and `compile_r_class_jar` so remote full build can sync both sets locally.
- `ModuleBuildPathInfo.javaClassPath` selects newest by `lastModifiedTime` when both `intermediates/javac/<variant>/classes` and `compile<Variant>JavaWithJavac/classes` exist. `allClassPath` mounts only that one resolved Java output to avoid an old directory shadowing new classes after AGP upgrade.
- When reading dependencies, `readProjectInfo.gradle.kts` uses previous project info for CRC caching but cannot rely on cache alone because transitive dependency information may be incomplete.
- `:idea:prepareSandbox` must package repository `third_party` (excluding `sources` payload), root `THIRD_PARTY_NOTICES.md`, generated `SOURCE.md`, and source checksums under `jugg/third_party`. Corresponding source stays at public immutable Git revisions identified by `SOURCE.md`. After `:idea:buildPlugin`, `verifyThirdPartyCompliance` checks a 104-row component inventory, fixed license selection, license/source location/modification declaration, repository source SHA-256, CI source Git state, absence of source payload in plugin, compressed compliance data ≤256 KiB, and SPDX 2.3 SBOM for 104 packages. Missing/mismatched third-party assets must fail release build, not warn.
- Included builds copy their `gradle_project_infos.json` as `include_build_N_gradle_project_infos.json`; the main project references them only through a list file.
- Inject included-build project-info tasks only at composite-build root; with no included builds, add no tasks or changes to read timing.
- When an included-build snapshot is missing this round, retain prior valid copy at the same index. Skip from list only if no old copy exists, so a transient read failure does not wipe usable metadata.
- IDE may collapse same-name modules from different Gradle builds into one simple name. If names match but relative paths differ, fully retain Gradle-side Application only if it is explicitly `Application`, comes from primary Gradle snapshot, and has a real R.jar. `ModuleBuildPathInfo.rFilePath` selects newest among several R.jar candidates by modification time. Otherwise use existing field merge; ordinary Library is unaffected. Conflict logs include IDE/Gradle module paths, primary-snapshot membership, candidate R.jar files, and final choice.
- Merger restores Gradle-confirmed module dependencies omitted by IDE snapshot when targets remain in final module set, including IDE-recognized and Gradle-only targets. It adds only missing edges, never removes or replaces IDE dependencies. Before adding, traverse current dependency graph from target to owner; if an edge would create a cycle, warn and skip. Successful-edge debug logs include IDE snapshot time, owner/target paths, and Gradle snapshot source. If same-name targets come from distinct module paths, warn as well to expose stale snapshot or composite-build identity ambiguity.
- Diff mode writes dependency differences and removes temporary project info only; non-diff mode writes formal `gradle_project_infos.json`.
- User confirmation of dependency diff is a correctness boundary. Do not turn `CHANGED_NOT_SYNCED` directly into `INCREMENTAL_COMPILE` for “automation.” On diff failure or user refusal, preserve Gradle rebuild semantics. Even with no dependency changes, incremental may continue only after the user explicitly chooses to ignore build-file changes.
- Inject androidTest tasks before Gradle task-graph finalization. If requested task name does not match actual task path, injection silently logs “no requested task found” and skips.
- CLI Run Configuration files contain remote-build passwords. Write with temporary file + atomic replacement and restrict POSIX read/write to current user. Logs/diagnostics must not print passwords or raw remote Gradle commands. Actual transmission of remote environment variables remains unrestricted, but logs may display full values only for `JAVA_HOME`, `ANDROID_HOME`, `ANDROID_SDK_ROOT`, and `GRADLE_USER_HOME`; for `PATH` log only that it is configured, and for other variables only names and count. SSH shell must successfully disable PTY echo before sending a command with environment variables; if unable to confirm, stop remote compilation rather than expose echoed command.

## 7. Investigation Entry Points

| Symptom | Start with |
|---|---|
| Gradle root differs from IDE project root | Handling of `jugg.projectDir` in `GradleProjectInfoReaderManager`. |
| Module source/res/Manifest paths wrong | `GradleProjectInfoReader.getModuleInfo()` and `ModuleBuildPathInfo`. |
| R.jar / Manifest / Data Binding output missing after AGP upgrade | Relevant `ModuleBuildPathInfo` property. |
| R class exists but fields are missing, or library resource fields disappear | Single R provider selected by `BaseCompileContext.getGradleRFilePaths()` and `module compile R.jar candidates found in module` debug log; compare `lastModified` of `compile_r_class_jar` and `compile_only_not_namespaced_r_class_jar`. |
| Project-info JSON lacks a field | `ModuleInfo` synchronization checklist, `ProjectInfoSerializerInGradle`, `JuggProjectInfoMerger`. |
| Incremental output remains obfuscated after disabling minify, or mapping is missing after enabling | `variants[].minifyEnabled` in `gradle_project_infos.json`, `ModuleInfo.minifyEnabled`, and `ICompileContext.isMinified`. `minifyEnabled=null` means stale snapshot or unreadable AGP setting and needs successful Gradle read. |
| DataBinding enabled but incremental reports `data binding is not enabled` | `ProjectInfoSerializer` Groovy `useDataBinding` read alias, then whether merger keeps `isUseDataBinding`. |
| Incremental D8 assertion/incompatibility after AGP upgrade | `JuggProjectInfo.agpR8Classpath`, `GradleProjectInfoReaderManager.findAgpR8Classpath()`, `DexFileMaker`. |
| Included-build module missing | `gradle_include_builds.txt` and `JuggProjectInfoMerger`. |
| Same-name app merges to external project's R.jar | Primary Gradle Application + real-R.jar guard logs in `JuggProjectInfoMerger`. |
| APK output missing after custom build directory | `ModuleBuildPathInfo.buildDirRelativePath`, `AsDeployerCompat.getSuggestRunConfigurations()`, `LocalGradleCompileClient`, `FindOutputCommand`. |
| Dependency changes missed or confirmation differs by Runtime | `GradleDependencyDiffer`, `DependencyChangeManagerByGradle` / `DependencyChangeManagerBySync`, and relevant `CompileUiHandler`. |
| Library androidTest target package wrong | Actual Test APK Manifest, `buildAndroidTestModuleInfo()`, `LibraryTestApkBuildHistory`. |
| Default/custom Compose-resource directory missed | `GradleProjectInfoReader.getComposeResourceInfo()`, `readComposeResourceDirectories()`, and serialized `composeResourceInfo`. |
| Compose-resource API unsupported | Task-type set/required properties, task class code source, generator class/method/constructor shape, and `unsupportedReason`. |
| `-I readProjectInfo.gradle.kts` reports trailing commas / Expecting an argument | Trailing-comma cleanup in `buildReadProjectInfoScript.gradle`; run `ReadProjectInfoScriptContentTest` and Gradle 5/6 compatibility regressions per `06_testing.md` §7.4. |
| C++ incremental reports `App strip task strip<X>DebugSymbols was not found in :app` | APK owner was not configured under Configuration on Demand in this invocation. Check unique `moduleRootDir + variant` entry in `build/jugg/classpath/native_strip/config.json` and whether referenced `backupPath` / `sourcePath` remains executable. If missing, run a full Gradle build to refresh cache; do not add owner strip/merge tasks to this graph just to read config. |
| Dart/C/C++/Flutter asset/CMake configuration edit does not trigger external build | First confirm in `compile_latest.log` that the file reached before-filter/ChangedFile. Then inspect coverage by `externalBuildInfos.inputDirs`, `configFiles` / `excludedDirs`, task/native-output metadata, current-variant Flutter/native task, and `FileChangesHandler` context update. If task ran but a new directory still does not trigger, inspect completeness of `juggCollectExternalBuildInfo` invocation result and targeted project-info merge. |

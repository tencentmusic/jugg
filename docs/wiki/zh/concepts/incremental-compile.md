# 增量编译

Jugg 的增量编译目标是：**只处理本轮真正变化的文件，并把产物交给后续部署链路使用**。它不是完整替代 Gradle，而是在已有 Gradle 构建产物基础上，尽量减少再次执行完整 Gradle 构建的次数。

> [!IMPORTANT]
> Jugg 依赖最近一次可用的 Gradle 构建结果。涉及构建脚本、依赖、变体或复杂插件行为时，仍可能需要回退到 Gradle。

## 一次增量编译做了什么

一次 Jugg Run 进入编译阶段后，大致会经历以下过程：

```text
收集文件变化
  -> 判断是否适合增量编译
  -> 按文件类型进入资源、源码、DEX、混淆等阶段
  -> 生成 staging 产物
  -> 分析是否还有受影响源码需要继续编译
  -> 将产物交给部署阶段
```

用户通常只需要关注三个结果：

| 结果 | 含义 | 下一步 |
|---|---|---|
| 增量编译成功 | Jugg 已生成本轮变化对应的部署产物 | 继续部署 |
| 增量编译失败但可回退 | 本轮变化不适合继续增量 | 执行或提示 Gradle 构建 |
| 增量编译失败且暂不回退 | Jugg 需要用户先确认错误或重新运行 | 查看编译日志 |

## Jugg 如何决定是否增量

Jugg 会先做一轮轻量检查。如果命中明显不适合增量的场景，会直接走 Gradle。

常见判断包括：

- 设备或部署状态是否可用。
- 文件变化是否过多。
- 是否切换了运行目标，例如从普通 App Run 切到 androidTest。
- 是否修改了 Gradle 构建文件或依赖。
- 上次完整构建状态是否可靠。
- 是否由用户主动选择强制 Gradle 构建。

这些判断的目的不是追求“永远增量”，而是避免在风险较高时生成不可靠产物。

## 编译阶段如何串起来

Jugg 会按文件类型进入不同子阶段。典型顺序是：

```text
assets / native lib
  -> res / AndroidManifest
  -> R.java / R.dex
  -> Java / Kotlin / class
  -> dex / minify
```

其中资源阶段可能生成 `R.java`、ViewBinding/DataBinding 相关源码，这些源码不会直接部署，而是继续交给源码编译阶段处理。

> [!NOTE]
> 用户不需要手动选择这些阶段。Jugg 会根据变化文件类型自动选择需要执行的部分。

## 为什么编译成功后还会继续编译

有些源码虽然没有被直接修改，但会受到已修改类的影响。例如：

- 修改了父类、接口或方法签名。
- 修改了可能影响调用方的常量或结构。
- release 场景下需要重新生成或重混淆相关产物。

因此，Jugg 在一轮编译成功后，还会做影响分析。如果发现需要补编译的源码，会继续进入下一轮。

```text
直接修改的文件编译成功
  -> 分析影响范围
  -> 找到受影响源码
  -> 继续编译受影响源码
  -> 直到没有新的受影响文件
```

这类“继续编译”是正常行为，不代表第一次编译失败。

## 与 Gradle 构建的关系

Jugg 增量编译和 Gradle 构建的关系可以理解为：

| 能力 | Jugg 增量编译 | Gradle 构建 |
|---|---|---|
| 处理小范围源码修改 | 优先使用 | 可处理 |
| 处理资源、Manifest 的常见修改 | 优先使用 | 可处理 |
| 处理复杂构建脚本变化 | 可能回退 | 权威路径 |
| 重新生成完整 APK/AAB | 不负责完整替代 | 权威路径 |
| 作为长期基线 | 依赖最近一次构建产物 | 生成基线产物 |

> [!TIP]
> 如果你不确定一次修改是否适合增量，可以先直接 Run。Jugg 会自动判断，必要时提示或回退。

## 什么时候更容易回退

以下场景更容易触发 Gradle：

- 修改了 `build.gradle`、版本目录、插件配置或依赖声明。
- 一次改动跨越大量源码文件或多个模块。
- 设备未连接、设备状态异常，或当前部署状态不可复用。
- 切换了 build target、运行配置或测试目标。
- 上次完整构建失败，当前缺少可信基线。

回退不是错误，而是为了让后续增量重新建立在可信产物上。

## 如何判断本轮是不是增量

可以从运行输出或日志中观察：

| 线索 | 说明 |
|---|---|
| `Compile files:` | Jugg 正在处理本轮变化文件 |
| `Detect effected sources` | 编译成功后发现受影响源码，正在继续补编译 |
| `fallback` / `Fallback` | 当前进入或即将进入 Gradle 回退 |
| `No file changes` | Jugg 没有发现可增量处理的文件变化 |

如果需要进一步排查，请继续看[编译问题排查](../troubleshooting/compile.md)。

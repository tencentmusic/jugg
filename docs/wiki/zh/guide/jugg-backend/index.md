# Jugg 后台

Jugg 可以连接一个 HTTP 后台，用于集中管理插件升级、热更新、项目默认配置、问题诊断和远端机器申请。后台不是运行 Jugg 的必需条件；如果不配置后台，增量编译、部署、CLI、MCP 等本地能力仍可使用。

公开构建不包含预置 `servers.json`，因此不会自动连接 Jugg 后台。团队内部使用 `buildPluginInternal` 将本地配置打入插件；用户明确设置的 Custom Server 在没有内置配置时仍然生效。

这组页面面向需要自建后台的团队。重点说明插件当前支持哪些后台能力、哪些接口可以最小实现、哪些能力属于可选增强。

## 能力总览

| 能力 | 用途 | 自建时是否必须 |
|---|---|---|
| 更新检查 | 告诉插件是否有新的完整插件包，并可展示通知 | 建议实现 |
| 项目配置下发 | 按项目下发服务器列表、编译规则、模块配置和自定义编译器 | 按需实现 |
| 事件上报 | 记录编译、部署、检查更新等行为结果 | 可选 |
| 问题日志上传 | 用户提交问题时上传 Jugg 日志包 | 建议实现 |
| 热更新 | 下载插件 jar 级别更新，必要时提示重启或重装 | 可选 |
| 自定义编译器分发 | 将团队自定义编译器 jar 下发给指定项目 | 按需实现 |
| 远端机器申请 | 在 IDE 内引导用户申请远端编译机器并回填配置 | 可选，通常依赖团队内部平台 |

## 插件侧调用模型

```text
Android Studio 启动或用户手动检查更新
  -> Jugg 请求后台检查版本和项目配置
  -> 后台返回通知、升级入口和 customConfigJson
  -> 插件应用项目默认配置

日常编译、部署、诊断
  -> 插件按需上报事件
  -> 用户提交问题时上传日志包

热更新检查
  -> 后台返回目标版本、更新说明和 jar 文件列表
  -> 插件下载缺失文件并校验 md5
  -> 根据结果提示继续使用、重启 IDE 或重新安装
```

# Jugg 后台远端机器申请

Jugg 后台可以提供一个交互式流程，在 IDE 内引导用户申请远端编译机器，并把远端连接信息返回给插件。这个能力主要服务远端 Gradle 场景，通常依赖团队已有的云开发机、账号认证和同步工具。

## 能力边界

适合：

- 团队已有内部云开发机或远端构建机平台。
- 远端机器可以通过 SSH 访问。
- 申请完成后能返回 IP、端口、账号、同步方式和远端目录。
- 希望用户在 IDE 内完成申请，不手动复制配置。

不适合：

- 没有统一远端机器平台。
- 远端环境需要复杂人工审批，无法通过接口确认完成状态。
- 账号、密码或 token 不允许经过 Jugg 后台。
- 只需要固定远端机器配置；这种情况直接在 Jugg 远端 Gradle 中配置即可。

## 交互模型

```text
用户在 IDE 发起申请
  -> 后台返回步骤列表和第一步内容
  -> 用户按步骤登录、选择编译方案、初始化机器
  -> 后台轮询外部平台状态
  -> 成功后返回 remoteServerInfo
  -> 插件把远端 Gradle 配置写入本地项目
```

`remoteServerInfo` 代表插件需要的远端连接信息，包括 SSH 地址、端口、账号、代理、同步模式和远端同步目录。

## 自建前提

- 有可脚本化或可接口化的远端机器申请流程。
- 能判断登录、初始化、申请失败和超时。
- 能把远端连接信息转换成 Jugg 远端 Gradle 可用配置。
- 能处理同一时间多个用户申请时的并发和隔离。
- 能在失败或用户退出时释放临时状态。

## 使用建议

- 把远端机器申请作为可选增强，不要作为 Jugg 本地运行的前置条件。
- 申请流程中只展示用户必须操作的步骤，不暴露后台命令细节。
- 不建议在后台长期保存明文密码、私钥或一次性 token。
- 如果团队使用 Windows 开发机，需要提前确认同步工具和路径规则。

# Windows rsync 探测失败诊断

## 问题与边界

2026-10-21 13:33:16、2026-10-22 08:13:51 的原始日志显示，本机 `ssh -V` 以 `0xC0000043` 退出。现有 best-effort 改动允许继续传输，但丢失探测失败状态。独立进程对照未复现，尚不能确认冲突路径或占用者。

## 实施

- 将 rsync/ssh 版本探测移到独立文件，原运行时只保留入口；单项探测异常局部收口，取消语义保留。
- 将原生进程诊断格式、字段筛选和日志失败隔离放到独立文件，执行器只在启动、结束和异常边界调用。
- 记录工具、白名单版本参数、父子 PID、耗时、真实退出码及十六进制状态；正常信息 debug，探测失败 warn 并说明继续实际流程。
- 不打印完整 argv、环境、异常原始消息，不新增复测、句柄扫描、系统追踪或等待。原 stdout/stderr 沿现有链路保留。
- 实际传输失败仍保留原退出码或异常；诊断日志故障不得改变进程结果。

## 验证

- 回归 owner：`WindowsRsyncRuntimeTest`（探测失败隔离、后续传输）、`CmdExecutorProcessTest`（真实进程结果、诊断信息边界、日志失败隔离及取消）。属于 L2 外部进程协作验证，不修改编译/部署编排。
- 自动化保护诊断字段和隐私边界、失败隔离等稳定契约，不锁定日志完整文案。
- 修改前两个定向用例失败：启动失败没有诊断日志、探测运行时异常阻断后续工作。
- 修改后执行 `:main:test --tests '*CmdExecutorProcessTest' --tests '*CmdExecutorCancellationTest' --tests '*WindowsRsyncRuntimeTest'`：17 项中 16 项通过，1 项 Unix shell 专用测试在 Windows 跳过；包括本机 Cygwin 链接恢复、真实子进程退出/取消、诊断日志故障隔离、参数隐私及线程中断传播。
- `git diff --check` 通过；人工核对新增日志按字符串 `+` 换行，正常路径无新增进程、复测、等待或扫描。未做性能基准，不声明零开销。
- ProcMon 取证仍需在 IDE 现场复现时手动采集；本改动不声称解决共享冲突根因。

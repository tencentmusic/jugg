# 远端编译 review 问题修复

## 失败证据与范围

- 普通 IDE Run 为 UI 和执行端分别创建运行参数；默认或相对远端目录只在执行端解析为绝对路径，原日志解析器跳过映射。参数复制还会产生相同问题。
- 自动密钥登录失败后，弹窗密码登录成功仍保留密钥列表。Windows rsync 因列表非空而禁用密码回退，导致登录成功但文件同步失败。
- Windows rsync 的依赖变化检测上传后直接执行 `./gradlew --dry-run`，遗漏完整构建已有的权限准备。当 Cygwin 读取到的源 wrapper 无执行位时，上传会覆盖远端权限。不能推断所有 NTFS 工程均会触发，也不把 POSIX 夹具当作 Windows/Cygwin 现场复现。

## 修复

- 由远端客户端把本次已解析的同步根目录通知当前输出监听器，日志解析器直接消费，避免依赖参数对象共享；保留显式目录与未解析时的原有行为。
- 密钥与密码并存时允许公钥优先、密码回退；保持仅密钥、仅密码的认证方式和凭据传输边界。
- 依赖检测在本轮上传后复用 wrapper 权限准备，明确使用它实际执行的工程根 `./gradlew`，不根据完整构建命令推断。

## 验证

- 测试价值门禁：远端诊断源码定位与 SSH 认证协议是稳定可观察契约，分别追加到 `GradleOutputParserTest` 和 `WindowsRsyncRuntimeTest`，不引入生产测试注入点。新增回归先失败，修复后通过；覆盖重新解析目录、显式目录、未解析输出、混合认证、仅密钥、仅密码及凭据不进入 argv。
- wrapper 复用已有权限准备，不新增只能跳过或扫描源码的测试。本地等价 Flow 执行真实 `fetchLibraryChanges()` 编排、Bash 命令和差异结果解析，平台选择及远端连接/传输边界由 mock 替代，实际文件覆盖使用本机 rsync：源 wrapper 为 `644`，上传将目标执行位置为关闭，流程重新设置执行位后成功运行并解析结果；完整构建命令特意配置为 `gradle --version`，确认依赖检测仍准备它实际使用的 `./gradlew`。同一 Flow 验证独立 UI 参数仍显示 `$HOME/remote` 时，接收 HOME 解析通知后的诊断已经正确映射到本地。
- 复用 review 的登录编排探针：自动密钥登录失败、弹窗密码登录成功后，密钥列表仍非空；后续真实 Windows rsync 参数允许公钥和密码，batch 模式关闭，askpass 环境包含密码。当前环境没有 Windows/Cygwin 与真实远端测试配置；上述结果不代表已实测 Windows ACL、Cygwin 进程或真实 SSH 服务端。
- 定向测试：main 层 69 项、idea 层 18 项，共 83 项通过，4 项 Windows 专用测试跳过；包含进程执行、取消、SSH 登录、同步过滤、运行参数、日志解析和 ASK AI handler，IDE 与核心代码编译通过。
- Wiki 判断：本次恢复既有远端编译、认证回退与诊断行为，未改变用户操作、配置项或支持范围；无需修改 Wiki。

3.0.13 (2026.06.08)

  1. [feature] 支持 Jugg CLI skills，让 AI coding agent 可以独立快速完成开发到验收闭环
  2. [feature] 支持 android test 增量编译
  3. [feature] 支持 release APK 增量编译，支持 R8 混淆和 AabResGuard 资源混淆
  4. [feature] 支持 KSP（暂时仅对 kuikly @Page 启用）
  5. [feature] 支持常量扩散编译
  6. [feature] Windows 和 Linux 支持 target api 35 资源增量编译
  7. [feature] 支持 Gradle 9.2.1
  8. [optimize] 优化降级后编译初始化时容易出现 IDE 卡住一段时间的问题，现在改为独立进程完成 APK 字节码解析
  9. [optimize] 优化部分场景需要重启 App 1-2 次，简化部署流程。解决方案：实现新的部署通道，不强依赖 apply changes 部署通道
  10. [optimize] 大量类部署（>2000) 时自动触发 dex 合并，修复大量类触发启动 OOM 问题
  11. [optimize] 提高 databinding 部分场景的编译兼容性，如同时修改数据类和 XML 时会编译失败，工程使用 Kotlin 1.7 版本会编译失败等
  12. [optimize] 修复 Windows 执行 gradle clean 失败，提示日志文件被占用无法删除。改为无锁写入
  13. [bugfix] 修复 AbstractMethodException，场景：编译多层级 gradle 模块的 Kotlin internal 方法时，概率出现 module-name 和 base APK 不一致
  14. [bugfix] 修复首次编译时，文件无法识别未被 git add 的文件的问题
  15. [bugfix] 修复多项目同时打开且 Kotlin 版本不一致时，容易出现编译失败。原因：多项目共享了同一个编译器实例
  16. [bugfix] 修复使用 ./gradlew clean assembleDebug 时编译失败的问题，原因是 clean 会删除 Jugg 必需的编译产物，现已移至 .gradle/jugg 目录
